# Серверная часть: Телеграм-бот

Две функции. Одна принимает сообщения кандидатов, вторая отправляет ответы.
Токен бота не лежит ни в одной из них — он приходит из секретов проекта.

| Функция | Кто её вызывает | Что делает |
|---|---|---|
| `telegram-webhook` | Телеграм | Кладёт входящее в `messages`, при первом контакте заводит карточку кандидата |
| `telegram-send` | Database Webhook на `INSERT` в `messages` | Доставляет исходящее в чат, проверив лимит касаний |

Приложение об этом не знает: при отправке оно просто пишет строку
в `messages`. База — источник правды, доставка — отдельная забота. Поэтому
сообщение уйдёт одинаково, откуда бы его ни отправили: из «Переписки»,
из автодействия этапа или из будущего ИИ-автопилота.

## Что осталось — и почему это делаете вы

Три шага. Все три касаются секретов, поэтому руками их вводите вы:
токен не должен попасть ни в код, ни в переписку, ни в историю команд.

### 1. Токен бота

`@BotFather` → `/newbot` (или `/mybots` → ваш бот → **API Token**).

Если токен где-то засветился — **Revoke current token**. Отозванный токен
перестаёт работать сразу, сам бот при этом остаётся.

### 2. Секреты проекта

**Edge Functions → Secrets → Add new secret**, две штуки:

| Имя | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от BotFather |
| `TELEGRAM_WEBHOOK_SECRET` | любая длинная строка, которую придумываете вы |

`TELEGRAM_WEBHOOK_SECRET` знают только Телеграм и функция — по нему она
отличает настоящий вызов от чужого. Пока его нет, вебхук отвечает `403`
на всё подряд: закрыт, а не дырявый.

### 3. Доставка исходящих

**Database → Webhooks → Create a new hook**

| Поле | Значение |
|---|---|
| Table | `messages` |
| Events | `Insert` |
| Type | Supabase Edge Function |
| Function | `telegram-send` |

Authorization панель подставит сама — ключ проекта при этом нигде не
показывается и никуда не копируется.

### 4. Регистрация адреса у Телеграма

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
  -d "url=https://bzsujgcsavopvgobqsus.supabase.co/functions/v1/telegram-webhook" \
  -d "secret_token=<ТОТ ЖЕ TELEGRAM_WEBHOOK_SECRET>"
```

Проверить, что Телеграм доволен: `getWebhookInfo` тем же способом.
В ответе `pending_update_count` должен быть нулём, а `last_error_message`
— пустым.

## Как проверить, что работает

1. Напишите боту что-нибудь со своего аккаунта.
2. В приложении откройте **Переписка** — там должен появиться новый диалог,
   а в базе — карточка кандидата с вашим `telegram_user_id`.
3. Ответьте из приложения. Ответ придёт в Телеграм.

Если тишина — логи функции: **Edge Functions → telegram-webhook → Logs**.

## Что осознанно не сделано

**ИИ-автопилот (фишка 12).** Функция кладёт сообщение в базу, но не отвечает
сама. Для этого нужен ключ модели и отдельное решение о том, где проходит
граница: на какие вопросы ассистент отвечает сам, а какие обязан передать
человеку. Ошибиться здесь дороже, чем не сделать: кандидат, которому бот
наврал про зарплату, — это потерянный кандидат и испорченная репутация.

**Согласие на обработку данных.** Новый кандидат заводится с
`consent_pd_granted = false`. Согласие нужно брать явным шагом в диалоге,
а не выводить из того, что человек что-то написал. Пока этот шаг не
сделан — по 152-ФЗ данные собраны без основания.
