# Растим · платформа найма

Работающее приложение плюс комплект для сборки в **Lovable** на **PostgreSQL**
(Supabase): системные промпты, схема базы с ролями и политиками доступа,
дизайн-система в токенах.

Собрано из двух ваших документов: таблицы `HR.xlsx` (стейкхолдеры, 64 фишки,
разбор конкурентов, монетизация архива) и файла дизайн-системы
`designsystem-light.html`.

Продукт отраслево-нейтральный: направление, уровень, навыки, документы
и практическая проверка одинаково работают в любой сфере. Под конкретную
отрасль настраиваются справочники, а не структура.

## Запустить прямо сейчас

```bash
npm --prefix app install
```

```bash
npm --prefix app run dev
```

Ключи не нужны: без них приложение идёт в демо-режиме на встроенных данных
и предлагает войти любой из семи ролей. Подробности — в [app/README.md](app/README.md).

## Три решения, вокруг которых собрано всё остальное

**1. Кандидат и отклик — разные сущности.**
Человек живёт в базе навсегда, отклик — на конкретную вакансию. Через пять
лет откликнулся снова, а вся история общения на месте. Это закрывает боль
«общался два года назад — переписки нет» и делает архив ресурсом, а не свалкой.

**2. Критерии вместо балла.**
`application_criteria_results` хранит по каждому критерию не оценку, а
результат плюс **цитату-основание** и источник (резюме, интервью, кейс,
практическая проверка). Интерфейс показывает «4 из 6», клик раскрывает,
какие и чем подтверждены. Балл без основания HR не защитит перед руководителем.

**3. Права — в базе, а не в интерфейсе.**
Роли лежат в отдельной таблице `user_roles`, доступ проверяется функциями
`SECURITY DEFINER`, зарплата и заметки вынесены в отдельные таблицы со своими
политиками. Скрыть поле на фронте — не значит скрыть его: оно видно в сетевом
запросе.

## Семь ролей

`superuser` · `director` · `hr_manager` · `dept_head` · `line_manager` ·
`employee` · `candidate`

Роли комбинируются. Для `dept_head` и `line_manager` действие роли
ограничивается подразделением и всеми его дочерними.

Три места, где право ограничено намеренно:
- базу кандидатов не видит руководитель подразделения — только откликнувшихся к нему;
- вилку не видит непосредственный руководитель;
- журнал аудита не видит никто, кроме суперпользователя.

Подробная матрица — в `03-roles-and-screens.md`.

## Границы MVP

**Работает в приложении:** воронка и канбан с автовыдачей заданий, карточка
отклика, критерии с основанием, сравнение кандидатов рядом, подбор из архива,
поиск по базе на обычном языке, заявка на подбор, согласование и версии
требований, вопросы под роль, календарь и самозапись, оффер с согласованием,
практическая проверка с оценочным листом, документы с блокировкой оффера,
SLA и эскалация, зарплатная аналитика, причины отсева, дашборд,
согласия и право на забвение, роли и права. Полная сверка — в
[app/FEATURES.md](app/FEATURES.md).

**Работает на сервере:** Телеграм-бот ведёт весь путь кандидата в переписке,
вакансия уходит на hh кнопкой и отклики возвращаются в ту же воронку. Код —
в [supabase/functions/](supabase/functions/), подключение — в
[supabase/README.md](supabase/README.md).

**Нужен ключ модели:** разбор резюме, саммари созвонов, ответ ассистента
за рекрутера, обратная связь по кейсу через ценности. Таблицы, экраны и место
в потоке готовы; промпты для edge functions — шаги 13–15 в
[04-lovable-build-steps.md](04-lovable-build-steps.md).

**Жизнь после найма** — онбординг 30/60/90, ИПР, наставничество, материалы,
оценка на испытательном — сначала была вынесена во второй продукт, а потом
вернулась: оценка на испытательном по критериям отбора это единственный
ответ на вопрос «тех ли мы берём». Почему передумали — в
[app/FEATURES.md](app/FEATURES.md).

## Что нужно доделать руками до запуска

Три вещи, которых нет в этих файлах и которые за вас никто не решит.

1. **Ценности компании.** В `sql/06_seed.sql` лежат пять ценностей-заготовок
   с эталонными ответами. Замените на свои. Без формализованных ценностей
   ИИ-обратная связь по кейсам — ваше самое сильное отличие — будет лить воду.
2. **Согласие на обработку данных и на запись созвонов.** Нужен юридический
   текст. Таблица `consents` и журнал готовы, текста в них нет. Разбор
   собеседований без согласия незаконен.
3. **Стоимость простоя вакансии** по каждому подразделению
   (`departments.cost_per_idle_day`) и стоимость часа HR
   (`company_settings.hr_hour_cost`). Замерьте текущую стоимость найма
   **до** запуска платформы — иначе через полгода не с чем будет сравнить.
