# Растим · приложение

React + TypeScript + Vite + Tailwind, база — PostgreSQL через Supabase.
Тот же стек, что генерирует Lovable, поэтому код переносится туда как есть.

## Запуск

```bash
npm --prefix app install
```

```bash
npm --prefix app run dev
```

Откроется `http://localhost:5173`. Ключи не нужны: без них приложение идёт
в **демо-режиме** на встроенных данных и предлагает войти любой из семи ролей.

## Два режима

| | Демо-режим | С базой |
|---|---|---|
| Когда | `.env` пуст или его нет | заданы `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` |
| Данные | встроенный набор в `src/lib/demoData.ts` | PostgreSQL |
| Вход | выбор роли одним кликом | почта и пароль |
| Права | роутер прячет чужие экраны | **RLS в базе** |

Переключение не трогает ни один экран: весь доступ к данным идёт через
`src/lib/api.ts`, и ветка режима живёт только там.

### Подключить настоящую базу

1. Примените миграции из `../sql/` по порядку 01 → 06.
2. Скопируйте `.env.example` в `.env` и впишите URL и anon-ключ проекта.
3. Перезапустите `npm run dev`.
4. Зарегистрируйтесь через интерфейс и выдайте себе роль суперпользователя —
   запрос лежит в конце `../sql/06_seed.sql`.

```
src/
  lib/
    api.ts          единственная точка доступа к данным, обе ветки режима

    ui/             кнопки, поля, карточки, таблица, вкладки, модалка

```

### Экраны по ролям

| Роль | Стартовый экран | Меню |
|---|---|---|
| Руководитель | `/dashboard` | Дашборд, Вакансии, Согласования, База, Документы, Аналитика |

## Три правила, которые нельзя нарушать при доработке

**1. Роль не приходит с клиента.** `useRoles` читает `user_roles` из базы.
Если роль переехать в профиль или в localStorage, любой пользователь сделает
себя суперпользователем обычным запросом на обновление своей строки.

**2. `RoleGate` — удобство, а не безопасность.** Настоящее ограничение стоит
в RLS: даже если обойти роутер, база вернёт пустой ответ. Проверять новый
экран нужно запросом от имени чужой роли, а не глазами.

**3. Цвет только из токенов.** Ни `bg-blue-500`, ни `#2B60AC`, ни
`style={{ color }}` в разметке. Единственное исключение — цвет этапа воронки:
он приходит из базы токеном (`stage-3`) и подставляется как
`hsl(var(--${token}))`. Значение цвета всё равно остаётся в `index.css`.

## Чего в приложении сознательно нет

Телеграм-бот, разбор резюме, саммари созвонов и обратная связь по кейсу
показаны как данные, но не подключены к модели: для них нужны edge functions
и ключи, которые не должны попадать в клиентский код. Промпты для них —
шаги 13–15 в `../04-lovable-build-steps.md`.

Онбординг, ИПР, наставничество и рефералы вынесены во второй продукт.
Таблицы под них есть в `../sql/04_employees_analytics.sql`, интерфейса нет —
и это решение, а не недоделка: они размывают первую версию.
